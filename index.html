percall_mcp.py is a zero-dependency stdio server (6 tools: block number, call, receipt, logs, balance, free). Your agent's Arc USDC wallet pays per call automatically — free tier kicks in until credits run out.

# 1) any request answers with 402 + price
curl -s -X POST https://api.percall.io/arc/ \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_blockNumber","params":[]}'

# 2) sign a USDC transferWithAuthorization (EIP-712) for the quoted amount
#    -> retry with the X-PAYMENT header (base64 payload)

# or, skip signing for light use:
curl -s -X POST https://api.percall.io/arc/ \
  -H 'X-From: 0xYourWallet' \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_blockNumber","params":[]}'   # 50 free/day
# once: sign ONE USDC authorization for your whole budget (24h-7d validity)
curl -s -X POST https://api.percall.io/topup \
  -H 'Content-Type: application/json' \
  -d '{"x402Version":2,"scheme":"exact","network":"5042",
       "payload":{ from,to,vault, value:"1000000", validBefore, nonce, v, r, s }}'

# -> settles on-chain in ~5s, credit granted
# after: every call just carries X-From: 0xYourWallet
#    (off-chain deduction, zero per-call gas, failed settles auto-revoke)

prepay is a prepaid card: the authorization is pulled exactly for the top-up amount, single-use nonce, expires per your validBefore.

how it works

01
402 — price first
every unpaid request returns HTTP 402 with the exact per-method price in USDC and the payment requirements. No keys, no accounts, no "contact sales".
02
sign — one authorization
you sign a USDC EIP-3009 transferWithAuthorization for the amount. For regulars: sign once per week via /topup and never sign again per-call.
03
settle — on-chain, ~5s
the payment settles to our vault on Arc (~1s blocks, USDC is the gas token). Failed settles auto-revoke your credit. Margin stays ~95% because gas is amortized over credits.

faq

what is x402?
An open payments protocol built on the HTTP 402 "Payment Required" status code (Coinbase, x402-foundation, 6.6k★, with working groups from Google/Solana-ecosystem contributors). The buyer signs a token authorization; the seller (or a facilitator) settles on-chain. We self-facilitate: verification is done by us, settlement is a direct USDC pull — no middleman custody.
what is "USDC" on Arc — is it the same USDC?
Arc (chainId 5042) is Circle's EVM chain where USDC is the native gas token. The same balance is readable as native (18 dec) or ERC20 (6 dec) — one ledger, two views. Your USDC pays for data and for the gas that settles it. No wrapping, no bridging.
where does my USDC go? can it be taken twice?
To a public vault address, exactly the amount you authorized, once per nonce (EIP-3009 nonces are single-use on-chain). Per-call payments settle the call's amount; /topup settles your top-up amount. If our settlement tx reverts, your credit is auto-revoked — you pay for what you got.
why is it this cheap?
We run our own multi-endpoint free RPC pool (rotation across keyless public endpoints + paid fallbacks), so upstream cost ≈ 0, and prepaid credits amortize one ~112k-gas settlement across hundreds of calls. The price is for availability + early data, not for gas.
isn't RPC free everywhere?
Free RPCs need keys, project approvals, and rate limits — friction every agent framework has to solve. x402 removes the account: capability = a wallet. And on new chains the free endpoints are scarce and flaky; paid-per-call with 99%+ settlement success is a different product. The data + report endpoints (/early /alerts /audit /whales /deployments /wallet-report /token-report /meme /score /price) are where the value concentrates.
which chains next?
MegaETH (4326) is in test, then whatever our deployment radar flags: a new EVM chain with a stablecoin gas token gets a percall instance within hours. Each chain = its own subdomain and bazaar listing.
